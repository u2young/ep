IoT物联网 · 使用指南

连接万物、统一模型、规则驱动、实时反馈 —— 设备接入与管理的全生命周期平台

它能做什么

面向设备运维与产品经理的 物联网设备管理平台。以「产品 → 物模型 → 设备」为主线：先定义产品与协议，再为产品建模（属性/服务/事件），最后逐台登记设备并激活。设备上下行消息全程留痕，配合告警规则实现「数据上报 → 阈值匹配 → 自动告警」闭环。

菜单功能说明

菜单用途
产品档案产品定义：ProductKey、节点类型（直连/网关/子设备）、接入协议（MQTT/HTTP/COAP/TCP 等）、数据格式与认证方式
产品分类多级分类树，组织管理产品档案
物模型按产品定义三要素：属性（可读/可写/读写）、服务（可调用方法）、事件（info/alert/error 级别上报）
设备管理设备登记与生命周期：未激活 → 在线/离线 → 禁用；含密钥、固件版本、最后在线时间
设备消息上下行消息日志：属性上报、属性读写、服务调用、事件、上下线，支持按设备/类型/方向排查
告警规则基于物模型属性配置阈值告警（如温度 > 80℃），含严重级别
告警中心规则命中的告警实例，集中查看与处理
告警日志告警处理动作留痕（确认/处理/关闭）

快速上手

  1. 建分类：在「产品分类」规划品类树（如 智能家居 → 传感器）
  2. 建产品：在「产品档案」创建产品，选择节点类型与接入协议，系统生成 ProductKey
  3. 定义物模型：为产品添加属性（如 temperature 温度）、服务、事件
  4. 登记设备：在「设备管理」添加设备并绑定产品，获取设备密钥
  5. 激活联调：设备按协议连接平台完成激活，状态转「在线」；在「设备消息」核对上下行数据
  6. 配告警：在「告警规则」设定阈值，触发后在「告警中心」跟进处理

场景示例：冷链仓库温控监控

「鲜达」冷链公司在 3 个仓库放了 120 台温湿度传感器，冷链要求库温 ≤ 8℃，超温 15 分钟内必须有人处理。

准备阶段：运维老张建产品「冷链温湿度传感器」（MQTT 直连），物模型里定义属性 temperature（可读）和 humidity，再把 120 台设备逐台登记，把设备密钥烧录进硬件。

上线：设备通电后 MQTT CONNECT 自动激活，列表里 120 台全部「在线」——不需要任何手工操作。每 30 秒一次温度上报，「设备消息」里能看到完整的上报流水。

配置告警：老张建规则「temperature > 8，持续 15 分钟，级别：严重」，绑定到三个仓库的所有设备。

某夜 2:14：三号仓冷机故障，温度爬到 12℃。2:29 告警触发，值班员在「告警中心」看到红色条目，到场重启冷机，2:50 在告警日志里记录「冷机重启，温度回落 5.2℃」，关闭告警。全程 36 分钟，损失可控——没有这套系统，第二天早上才发现就是一冷库报废货。

复盘：老张在「设备消息」按时间筛三号仓上报数据，看到温度从 8.3℃ 一路爬升的完整曲线，确认冷机是渐变故障而非传感器误报。

对应菜单路径：产品档案(定义) → 物模型(temperature/humidity) → 设备管理(登记/激活) → 告警规则(阈值) → 告警中心+告警日志(处置闭环) → 设备消息(取证复盘)

数据生命周期

① 配置资产链：定义在先、设备在后

产品分类归类 → 产品档案(ProductKey)建模 → 物模型(属性/服务/事件)挂载 → 设备(获取密钥)
物模型属性标识符（identifier）是后续消息解析、告警规则匹配的共同基础——改模型要趁早

② 设备生命周期状态机（核心）

未激活(0)— 首次连接(MQTT CONNECT / 注册上报) → 在线(1)⇄ 心跳超时/断连 ⇄ 重连 → 离线(2)
任意状态— 「禁用」(强制踢出连接) → 已禁用— 「启用」→ 重置为未激活 / 自动重连在线
未激活 / 离线 / 已禁用— 「删除」→ 数据移除（在线设备不可删）
上下线由平台自动判定：MQTT 看心跳与遗嘱消息、HTTP 按上报超时判定；每次转换自动写 last_online_time / last_offline_time 并向规则引擎上报 ONLINE / OFFLINE 事件

③ 数据流：消息 → 规则 → 告警闭环

设备上报 / 指令下发→ 设备消息(全量留痕)→ 规则引擎匹配 → 告警中心— 确认/处理 → 告警日志(处理留痕)→ 关闭
设备消息是排查一切的依据；告警规则基于物模型属性阈值（如温度 > 80℃），属性上报即匹配

④ 数据关联与终点

产品1 → N设备1 → N设备消息 　告警规则1 → N告警1 → N告警日志
终点规则：产品/设备/规则均为逻辑删除；设备消息与告警日志是运行凭证，只增不改，不随设备删除而清理

使用提示

  • 状态机设备按钮操作（激活 / 启用 / 禁用）受状态机约束，禁用设备不能收发消息
  • 物模型先行建议先完善物模型再量产设备，属性标识符（identifier）是消息解析与告警规则的基础
  • 排查顺序设备不在线 → 查设备状态与密钥；数据没上报 → 查「设备消息」里是否有记录；没触发告警 → 查规则阈值与属性标识符是否匹配
